## 1.1 시스템 아키텍처 개요

QuoteOn은 영업사원이 고객 상담 중 제품을 탐색하고 견적서를 작성·관리할 수 있도록 프론트엔드와 백엔드를 분리한 REST API 기반 웹 애플리케이션이다.

- **프론트엔드:** React + Vite
- **백엔드:** Spring Boot Web (Spring MVC)
- **데이터베이스:** MySQL
- **데이터 접근:** Spring JDBC (JdbcTemplate, RowMapper)
- **이메일 전송:** 네이버 메일 SMTP
- **테스트:** JUnit

프론트엔드는 사용자 화면을 제공하고 HTTP 요청으로 백엔드 API를 호출한다. 백엔드는 Controller, Service, Repository 계층으로 요청을 처리하며, Repository에서 MySQL 데이터에 접근한다. 견적서 이메일 전송은 백엔드에서 네이버 메일 SMTP를 통해 처리하고, 전송 결과를 데이터베이스에 기록한다.

## 1.2 기술 스택 선정 및 선정 이유

### 1.2.1 프론트엔드 (React + Vite)

- **선정 이유:** 컴포넌트 기반으로 화면을 구성할 수 있으며, Vite를 통해 빠르게 개발하고 실행할 수 있다.
- **주요 역할:** 로그인, 회원가입, 제품 목록, 고객 관리, 상담 작업대, 견적서 및 관리자 화면 구현.

### 1.2.2 백엔드 (Spring Boot Web / Spring MVC)

- **선정 이유:** REST API를 간편하게 구성할 수 있으며, Controller와 서비스 로직을 분리하여 관리하기 쉽다.
- **주요 역할:** 회원 인증 및 권한 확인, 제품 및 고객 관리, 견적 작성·조회·수정·삭제, 견적 금액 계산, PDF 견적서 생성 및 이메일 전송, 관리자 기능 처리.
- **처리 기준:** 견적 발송 성공 시에만 견적 상태를 발송 완료로 변경하며, 발송에 실패한 경우 발송 완료 상태로 변경하지 않는다. 발송 완료된 견적은 수정할 수 없으며, 변경이 필요한 경우 새 견적을 작성한다.

### 1.2.3 데이터 접근 (Spring JDBC)

- **선정 이유:** SQL을 직접 작성하여 데이터 조회 및 변경 과정을 명확하게 제어할 수 있다.
- **주요 역할:** JdbcTemplate을 이용한 SQL 실행 및 RowMapper를 이용한 조회 결과의 Java 객체 매핑.
- **데이터 처리 기준:** 견적 삭제 시 관련 견적 상세 내역과 해당 견적의 이메일 전송 이력도 함께 삭제되도록 처리한다. 관련 데이터 삭제는 데이터 정합성을 유지하도록 처리한다.

### 1.2.4 데이터베이스 (MySQL)

- **선정 이유:** 관계형 데이터를 구조적으로 관리하고 테이블 간 관계 및 제약 조건을 설정하기 적합하다.
- **주요 역할:** 회원, 고객, 제품, 카테고리, 견적서, 견적 상세 내역 및 이메일 전송 이력 저장.
- **데이터 관리 기준:**
  - 견적 번호는 자동 생성하며 중복을 방지하도록 고유 제약 조건을 적용한다.
  - 견적 상세 내역에는 견적 작성 시점의 제품명, 제품 코드, 판매가, 수량 및 금액을 저장하여 이후 제품 정보가 변경되어도 기존 견적 내용이 유지되도록 한다.
  - 제품의 기준 단가와 판매가를 구분하며, 견적 금액 계산에는 판매가를 사용한다.
  - 고객은 삭제 대신 활성/비활성 상태로 관리한다. 비활성 고객은 신규 견적에 선택할 수 없지만 기존 견적의 고객 정보는 유지한다.
  - 판매 중지된 제품은 신규 견적에 추가할 수 없지만 기존 견적 내역은 유지한다. 저장된 견적 또는 작성 중인 견적에서 사용 중인 제품은 삭제할 수 없으며, 사용하지 않는 제품만 삭제할 수 있다.
  - 회원 비활성화 시 기존 고객 및 견적 데이터는 유지하며, 비활성 회원의 로그인과 신규 견적 작성을 제한한다.
  - 금액은 소수점 정밀도를 지원하는 자료형으로 저장하고, 금액 계산 및 반올림 기준을 일관되게 적용한다.

### 1.2.5 이메일 전송 (네이버 메일 SMTP)

- **선정 이유:** 견적서를 이메일로 실제 전송하고, 고객에게 PDF 견적서를 전달하기 위해 사용한다.
- **주요 역할:** 수신자, 제목 및 내용을 입력받아 PDF 견적서를 첨부해 이메일 전송.
- **전송 이력:** 이메일 전송을 시도할 때마다 수신자, 전송 결과(성공/실패), 전송 시각 및 실패 사유를 데이터베이스에 저장한다. 전송 실패 건은 재전송할 수 있도록 처리한다.
- **보안:** SMTP 계정 비밀번호 등 민감한 정보는 소스 코드에 직접 작성하지 않고 환경 변수로 관리한다.

### 1.2.6 테스트 (JUnit)

- **선정 이유:** 주요 기능의 동작을 자동으로 검증하고 오류를 조기에 확인할 수 있다.
- **주요 역할:** 회원, 고객, 제품, 견적 금액 계산, 견적 상태 변경 및 이메일 전송 관련 서비스 로직 테스트.

### 1.2.7 개발 도구

- **IntelliJ IDEA:** Spring Boot 백엔드 개발.
- **Cursor:** React 프론트엔드 개발.
- **Git 및 GitHub:** 소스 코드 버전 관리.

### 1.2.8 보안 및 공통 처리 기준

- 비밀번호는 원문으로 저장하지 않고 단방향 해시 방식으로 저장한다.
- SMTP 비밀번호 등 민감 정보는 환경 변수로 관리한다.
- 백엔드에서 사용자 권한과 데이터 접근 권한을 확인한다.
- 날짜와 시간은 한국 시간 기준으로 일관되게 처리한다.
- 데이터베이스 초기 스키마와 초기 데이터는 `schema.sql`과 `data.sql`로 분리해 관리한다.
- PDF 생성 라이브러리는 별도 선정이 필요하며, 본 설계서에서는 특정 라이브러리를 확정하지 않는다.

## 1.3 시스템 데이터 흐름

1. **사용자 요청:** 사용자가 React 화면에서 로그인, 제품 검색, 고객 선택 또는 견적 작성 등의 작업을 수행한다.
2. **API 요청:** 프론트엔드는 HTTP 요청을 통해 Spring Boot 백엔드에 데이터를 요청하거나 전달한다.
3. **요청 처리:** Spring MVC의 Controller가 요청을 받고 Service에서 회원 권한 확인, 견적 계산 등 비즈니스 로직을 처리한다.
4. **데이터 처리:** Repository에서 JdbcTemplate을 이용해 MySQL에 SQL을 실행하고, 조회 결과는 RowMapper를 통해 Java 객체로 변환한다. 견적 저장 시에는 제품명, 제품 코드, 판매가, 수량 및 금액을 견적 상세 내역에 함께 저장한다.
5. **견적서 생성 및 전송:** 백엔드는 견적 데이터를 바탕으로 PDF 견적서를 생성한다. 사용자가 이메일 전송을 요청하면 네이버 메일 SMTP를 통해 PDF를 첨부해 전송한다.
6. **이메일 이력 저장:** 이메일 전송 시도 결과, 수신자, 전송 시각 및 실패 사유를 MySQL에 저장한다. 전송에 실패하면 견적 상태를 발송 완료로 변경하지 않으며, 실패 건은 재전송할 수 있다.
7. **응답 반환:** 백엔드는 처리 결과를 JSON 형태로 반환하고, 프론트엔드는 전달받은 데이터로 화면을 갱신한다.
